## 一、数组作函数参数（重点）

### 核心结论

> **数组传进函数会"退化"成指针，长度信息丢失。**

### 实测证据（`func_array.c`）

```
在 main 里:   sizeof(a) = 20  (整个数组)
    [函数内] sizeof(arr) = 8  <-- 退化成了指针, 拿不到长度
```

**同一个数组 `a`：**
- 在 `main` 里 `sizeof(a)` = **20**（5 × 4）
- 传进函数后 `sizeof(arr)` = **8**（指针大小）

### ⚠️ 所以这个写法是错的

```c
int wrong_length(int arr[])
{
    return sizeof(arr) / sizeof(arr[0]);   // ❌ 8 / 4 = 2，不是 5！
}
```

**实测：**

```
wrong_length(a) = 2   <-- 不是 5!
因为函数里的 arr 已经是指针, sizeof(arr)=8, 除以 sizeof(int)=4
```

**这个 bug 特别隐蔽** —— 编译能过、不报错、只是结果悄悄错了。**面试和实际项目里都很常见。**

### ✅ 正确做法：长度单独作为参数传

```c
int sum_array(int arr[], int n)     /* n 必须单独传 */
{
    int i, total = 0;
    for (i = 0; i < n; i++) {
        total += arr[i];
    }
    return total;
}

int main(void) {
    int a[5] = {10, 20, 30, 40, 50};
    int n = sizeof(a) / sizeof(a[0]);   /* 在 main 里算是对的 */
    printf("%d\n", sum_array(a, n));    /* 150 */
    return 0;
}
```

### `int arr[]` 和 `int *arr` 是同一件事

```c
int sum_array(int arr[], int n);   /* 写法 1 */
int sum_ptr  (int *arr, int n);    /* 写法 2 */
```

**实测：两个都返回 150，完全等价。**

**推荐用 `int arr[]`** —— 语义更清楚（告诉读代码的人"这里传的是数组"）。

### 函数里改数组，外面真的会变

```c
void double_all(int arr[], int n) {
    for (int i = 0; i < n; i++) arr[i] *= 2;
}
```

**实测：**

```
改之前:          [10, 20, 30, 40, 50]
double_all 之后: [20, 40, 60, 80, 100]
```

**因为传的是地址，函数直接改到了原始数组。**

**对比 `ex_b.c` 的 `swap_wrong`：传值改不动，传地址能改 —— 同一个道理。**

## 二、指针作"输出参数"（实用技巧）

### 要解决的问题

> **C 的函数只能 `return` 一个值。**
> **但用指针，就能"带回"多个结果。**

### 例子 1：swap（最基础）

```c
void swap(int *x, int *y) {
    int t = *x;
    *x = *y;
    *y = t;
}

int a = 3, b = 5;
swap(&a, &b);        /* 注意传的是 &a &b */
```

**实测：`a = 5, b = 3` 交换成功。**

### 例子 2：一次带回两个结果（最大 + 最小）

```c
void max_and_min(int arr[], int n, int *out_max, int *out_min) {
    *out_max = arr[0];
    *out_min = arr[0];
    for (int i = 1; i < n; i++) {
        if (arr[i] > *out_max) *out_max = arr[i];
        if (arr[i] < *out_min) *out_min = arr[i];
    }
}

int mx, mn;
max_and_min(data, 6, &mx, &mn);    /* 一次调用带回两个 */
```

**实测：`最大值 = 91   最小值 = 7`**

**只用 `return` 做不到这个。** 这是 C 里非常常用的手法。

### 例子 3：`return` 带一个，指针带其余的

```c
int stats(int arr[], int n, double *out_avg) {
    int total = 0;
    for (int i = 0; i < n; i++) total += arr[i];
    *out_avg = (double)total / n;    /* 指针带回平均值 */
    return total;                     /* return 带回求和 */
}

int total = stats(data, 5, &avg);    /* 求和 = 430, 平均 = 86.00 */
```

### 例子 4：用指针带回"成功与否"

```c
int safe_divide(double a, double b, double *out_result) {
    if (b == 0.0) {
        return 0;                 /* 失败 */
    }
    *out_result = a / b;
    return 1;                     /* 成功 */
}
```

**调用方：**

```c
double result;
if (safe_divide(10.0, 4.0, &result)) {
    printf("%.2f\n", result);     /* 2.50 */
}
if (!safe_divide(10.0, 0.0, &result)) {
    printf("除数为零\n");          /* 走这里，而且没去读 result */
}
```

**好处：用返回值报错，用指针带结果 —— 比直接崩掉好得多。**

### ⚠️ 陷阱：以为在函数里改指针能影响外面

```c
void wrong_pointer(int *p) {
    static int dummy = 999;
    p = &dummy;          /* ❌ 只改了"复印件"p 自己 */
}

int *p = &x;
wrong_pointer(p);
printf("%d\n", *p);      /* 还是 1，没变！ */
```

**原因：形参 `p` 是实参的复印件，改复印件不影响原件。**（和 `swap_wrong` 同一个坑）

**✅ 要改指针本身，得传"指针的地址"（二级指针）：**

```c
void right_pointer(int **p, int *target) {
    *p = target;         /* ✅ 通过二级指针，真的改到了外面 */
}

right_pointer(&p, &y);
printf("%d\n", *p);      /* 2，变了！ */
```

### 总结：什么时候要传地址

| 想让函数改什么 | 传什么 | 函数里怎么写 |
|---|---|---|
| 改一个 `int` | `int *` | `*p = ...` |
| 改一个 `int *` | `int **` | `**p = ...` |
| 改整个数组 | 数组名（就是地址）| `p[i] = ...` |
| **只读，不想改** | **直接传值** | `void print(int n)` |

## 三、返回指针的函数 + 野指针陷阱 ⚠️

### 回到开场那道题

```c
int *get_array(void) {
    int arr[3] = {1, 2, 3};
    return arr;      // ← 有问题吗？
}
```

### 答案：**有问题，而且很危险**（选第 3 个）

**为什么：**

```
函数里的局部变量放在【栈】上。
函数一返回，它占的那块内存就被回收了（会被别的函数覆盖）。
这时你手里的指针还指着那块地方
        ↓
    这就是【野指针 / 悬空指针】(dangling pointer)
```

### 实测证据（`func_return.c`）

```
[函数内] 局部数组 arr 的地址 = 000000000062FDD0
[函数外] 拿到的地址         = 000000000062FDD0  <-- 一样, 但那块地已经没了
=> 这块内存随时可能被覆盖, 读出来的数不可信, 写进去更危险
```

**⚠️ 更重要的：编译器会警告你！**

```
func_return.c:16:5: warning: function returns address of local variable
```

**看到这个警告千万别忽略。** 这就是为什么编译要加 `-Wall`。

### ✅ 三种正确做法

#### 做法 1：用 `static`（让数组活到程序结束）

```c
int *get_array_static(void) {
    static int arr[3] = {1, 2, 3};   /* static: 放在全局区，不随函数结束消失 */
    return arr;
}
```

**实测：**

```
[函数内] static 数组地址   = 0000000000403010     ← 注意是 0x40xxxx（全局区）
[函数外] 拿到的地址         = 0000000000403010
读出内容: p[0]=1 p[1]=2 p[2]=3                    ← 内容是对的
```

**地址对比很说明问题：**

| | 地址形态 | 位置 | 函数返回后 |
|---|---|---|---|
| 局部数组 | `0x62FDD0` | **栈** | ❌ 销毁 |
| `static` 数组 | `0x403010` | **全局/静态区** | ✅ 一直有效 |

**⚠️ 但 `static` 有个副作用：全程序只有一份，下次调用会覆盖上次的结果。**

#### 做法 2：调用者提供数组（⭐ 推荐）

```c
void fill_array(int *out, int n) {
    for (int i = 0; i < n; i++) {
        out[i] = (i + 1) * 10;
    }
}

int buf[5];
fill_array(buf, 5);      /* 结果写进调用者的数组 */
```

**优点：内存由调用者提供，谁负责释放很清楚，最不容易出错。**

#### 做法 3：返回静态字符串（只读，安全）

```c
const char *get_name(void) {
    return "pointer";    /* 不是局部变量，是常量区的字面量 */
}
```

**字符串字面量在只读数据区，一直有效 —— 但只能读，不能改。**

---

### 关键区别：返回「值」vs 返回「地址」

```c
int get_number(void) {
    int x = 42;
    return x;            /* ✅ 完全没问题 */
}
```

**为什么这个可以？**

| | 返回什么 | 结果 |
|---|---|---|
| `return x;` | **值的拷贝** | ✅ 安全（拷贝一份带走）|
| `return arr;` | **地址** | ❌ 危险（门牌号给你了，房子拆了）|

> **返回「值」= 拷贝一份带走；返回「地址」= 把门牌号给你，但房子已经拆了。**

**这是本节最重要的区别。**

## 四、本节总结

```
① 数组作参数会退化成指针，长度信息丢失
   → 长度必须单独传（int n）
   → 在函数里 sizeof(arr) 算长度是错的（会得到 2 而不是 5）

② int arr[] 和 int *arr 在参数里完全等价（推荐前者，语义清楚）

③ 指针作输出参数：让函数能"带回"多个结果
   → swap(&a, &b)
   → 想改 int   传 int *
   → 想改 int * 传 int **

④ 不要返回局部变量的地址（栈上的东西出了函数就没了）
   → 三种正确做法：static / 调用者提供数组 / malloc
   → 返回「值」是安全的，返回「地址」才危险

⑤ 编译时加 -Wall，看到 "returns address of local variable" 要当回事
```
