## 一、本章核心：指针的算术运算

### 最重要的一句话

> **`p + 1` 不是"地址加 1"，而是"往后挪一个元素"。**

挪多少**字节**，由 `p` **指向的类型**决定：

| 指针类型 | `p + 1` 挪几字节 | 为什么 |
|---|---|---|
| `char *` | **1** | `sizeof(char) = 1` |
| `int *` | **4** | `sizeof(int) = 4` |
| `double *` | **8** | `sizeof(double) = 8` |
| `int **` | **8** | `sizeof(int *) = 8` |

### 两个概念别混（我今天就混过）

```c
int a[5] = {10, 20, 30, 40, 50};
int *p = a;

printf("%ld", (long)((intptr_t)(p+1) - (intptr_t)p));  // 4  ← 字节差
printf("%ld", (long)((p+1) - p));                      // 1  ← 元素差
```

| 问法 | 答案 | 备注 |
|---|---|---|
| `p+1` 在**地址**上挪几字节 | **4** | 要把指针转成整数再减 |
| `p+1` 与 `p` 相差几个**元素** | **1** | 指针相减**天生**给元素个数 |

**规律：**

```
字节差 = 元素差 × sizeof(元素类型)
```

### 实测数据（我的机器）

```
p     = 000000000062FE30
p + 1 = 000000000062FE34      ← 30 → 34，差 4
p + 2 = 000000000062FE38      ← 34 → 38，差 4

&a[4] - &a[0] = 4             ← 4 个元素，不是 16 字节
```

## 二、各类型占多少字节（我的机器实测）

### ⚠️ 重要前提

**C 标准不规定死字节数，只规定"至少多大"，具体看平台。**
所以下面这些是**我这台机器**（64 位 Windows + MinGW gcc 4.9.2）的值。

### 整型

| 类型 | 字节 | 说明 |
|---|---|---|
| `char` | **1** | 范围约 −128 ~ 127 |
| `short` | **2** | |
| `int` | **4** | ⭐ 最常用 |
| `long` | **4** | ⚠️ **Windows 上是 4**，Linux 64 位是 8！ |
| `long long` | **8** | |

### 浮点

| 类型 | 字节 | 精度 |
|---|---|---|
| `float` | **4** | 约 6~7 位有效数字 |
| `double` | **8** | ⭐ 约 15~16 位有效数字 |
| `long double` | **16** | |

### 指针 ⭐ 全部一样大

```
char   *    8 字节
int    *    8 字节
double *    8 字节
void   *    8 字节
```

> **指针自己占多少字节，看系统位数（64 位 → 8 字节）。**
> **指针 `+1` 挪多少字节，看它指向的类型。**
> **这两件事完全独立，别混。**

### 为什么是 8 字节

```
地址 = 000000000062FE1C
       └──── 16 位十六进制 ────┘
       16 × 4 位 = 64 位 = 8 字节
```

**地址就是"内存门牌号"。64 位系统给门牌号留 8 字节，所以能表示 2⁶⁴ 个地址。**

### 数组

```
int    ai[5]   20 字节   (5 × 4)
char   ac[5]    5 字节   (5 × 1)
double ad[5]   40 字节   (5 × 8)
```

**数组大小 = 元素个数 × 单个元素大小**

## 三、三种等价写法（核心）

```c
int a[5] = {10, 20, 30, 40, 50};
int *p = a;
```

下面四个**完全等价**：

```c
a[0]        *(a + 0)        *p        *(p + 0)
```

### 为什么 `int *p = a;` 不用写 `&`

```
a  ≡  &a[0]        ← 数组名本身就是首元素的地址
```

### `a[i]` 的本质

```c
a[i]   ≡   *(a + i)
```

**`[]` 只是 `*()` 的语法糖。**

### ⚠️ 离谱但合法的 `2[a]`

```c
a[2]  = 30
*(a+2)= 30
2[a]  = 30      ← 居然也对！
*(2+a)= 30
```

**原因：加法满足交换律。**

```
a[2]  ≡  *(a + 2)  ≡  *(2 + a)  ≡  2[a]
```

`[]` 不要求顺序 —— **但别这么写！能跑不代表该写。**

**这个知识点的价值**：面试问"`a[i]` 底层是什么"，能答"`*(a+i)`，本质是指针运算"。

## 四、`sizeof` —— 数组 ≠ 指针的铁证

### 核心对比

```c
int b[4] = {100, 200, 300, 400};
int *q = b;

sizeof(b)    = 16     ← 整个数组：4 × 4
sizeof(b[0]) = 4      ← 一个元素
sizeof(q)    = 8      ← 只是个指针
```

### 对照表

| | 整个数组 | 一个元素 | 指针 |
|---|---|---|---|
| `int a[5]` / `int *p` | `sizeof(a)` = **20** | `sizeof(a[0])` = 4 | `sizeof(p)` = **8** |
| `int b[4]` / `int *q` | `sizeof(b)` = **16** | `sizeof(b[0])` = 4 | `sizeof(q)` = **8** |

### ❌ 我今天错的地方（重点记）

**我把 `sizeof(b)` 答成了 4** —— 那是 `sizeof(b[0])`（一个元素）。

```
sizeof(b)    → 整个数组（16）
sizeof(b[0]) → 一个元素（4）

少个下标，差 4 倍。
```

**还错了一道：** `sizeof(b) / sizeof(b[0])`

```
sizeof(b)    = 16   ← 分子：整个数组
sizeof(b[0]) = 4    ← 分母：一个元素
16 ÷ 4 = 4          ← 结果：有几个元素

不是 1！（我一开始答 1，误以为"元素÷元素"）
```

### 实用写法：自动算数组长度

```c
int n = sizeof(b) / sizeof(b[0]);    // n = 4
```

**好处：以后把 `b[4]` 改成 `b[10]`，`n` 自动变 10。**

## 五、⚠️ 数组名什么时候"退化"成指针

### 只有两种情况保持"整个数组"

1. **`sizeof(a)`** 里
2. **`&a`** 取地址时

**其他所有场合，数组名都退化成指向首元素的指针。**

### 实测

```
sizeof(a)    = 20   ← 不退化
sizeof(a+0)  = 8    ← 一参与运算就退化了！

&a 的地址 = 000000000062FE30
a  的地址 = 000000000062FE30   ← 数值相同，含义不同
```

### ⚠️ 致命陷阱：数组作函数参数

```c
void show_size(int arr[]) {
    printf("%u\n", (unsigned)sizeof(arr));   // 输出 8，不是 20！
}

int main(void) {
    int a[5];
    printf("%u\n", (unsigned)sizeof(a));     // 20
    show_size(a);                             // 8  ← 退化了
}
```

**实测输出：**

```
调用前:   sizeof(a) = 20
在函数里: sizeof(arr) = 8   ← 已经不是整个数组了！
```

**所以这个写法是错的：**

```c
void f(int arr[]) {
    int n = sizeof(arr) / sizeof(arr[0]);   // ❌ 8/4 = 2，不是 5！
}
```

> **数组当函数参数时，传递的其实是指针，长度信息丢了。**
> **必须额外传一个长度参数。**

这是新手最容易踩的坑之一，**7.4 会重点讲**。

## 六、今天踩的 3 个工具链坑（我犯的，记下来别重踩）

### 坑 1：中文乱码 —— 忘了 `utf8_console.h`

**现象：**

```
乱码：  ========== 閽?2[a] 涓哄渶涔堝悎娉?==========
正常：  ========== ⑤ 2[a] 为什么合法 ==========
```

**原因（我的笔记里早就写过）：**

> 编译器把源码里的中文按 **UTF-8** 存进 exe，
> 但 Windows 控制台默认用 **GBK（代码页 936）** 解码 → 乱码

**解决：`main` 第一行调 `enable_utf8_console();`**

```c
#include <stdio.h>
#include "utf8_console.h"

int main(void)
{
    enable_utf8_console();   /* ← 打印中文之前必须加这一行 */
    printf("中文正常\n");
    return 0;
}
```

**⚠️ 教训：写任何带中文输出的 .c 文件，第一件事就是加这两行。**

### 坑 2：gcc 4.9.2 不认 `%zu`

```c
printf("%zu", sizeof(a));              // ❌ warning: unknown conversion type character 'z'
printf("%u", (unsigned)sizeof(a));     // ✅ 能跑
```

**C99 的 `%zu` 是给 `size_t` 用的，我这个老版本 gcc 不支持。**

### 坑 3：指针转整数要用 `intptr_t`，不能用 `long`

```c
printf("%ld", (long)((p+1) - p));                        // ❌ warning
printf("%ld", (long)((intptr_t)(p+1) - (intptr_t)p));    // ✅
```

**因为 Windows 上 `long` 是 4 字节，指针是 8 字节 —— 位数不匹配。**

```c
#include <stdint.h>    /* intptr_t  —— 装"指针转成的整数" */
#include <stddef.h>    /* ptrdiff_t —— 装"两个指针之差" */
```
