三、★ 找到的主凶：LemuService.exe
------------------------------------------------------------

  服务名:   LEmuSVC
  路径:     D:\Program Files\Lenovo\FusionEngine\LEmu\LemuService.exe
  启动模式: Auto（开机自启）
  状态:     Running（一直在跑）

  这是什么：
    联想「FusionEngine / LEmu」组件
    目录里有 adb.exe / aapt.exe / libmemu.dll / libGLESv2.dll
    => 这是联想笔记本预装的【安卓模拟器】功能
       （在电脑上跑手机 App / 应用分身）
    => 它基于第三方模拟器 MEmu（逍遥模拟器）的技术

  崩溃记录（Application Log）:
    10-13 21:16   LemuService.exe 崩溃，faulting 模块 MSVCR100.dll
    10-13 21:17   连续崩溃 x3
    10-13 21:18   再崩
    10-12 20:07   崩溃（MSVCR100.dll）
    10-11 ...     也有

  时间关联（关键！）:
    21:16-21:18  LemuService 密集崩溃
    21:56        系统卡死 -> 你按电源
    22:00        开机，报告 ID 41

    => 崩溃集中在卡死前约 40 分钟

  另外:
    config.ini  修改时间 = 2026-10-13（今天）
    => 说明这个服务最近还在活动/自我修复


------------------------------------------------------------
四、为什么怀疑它
------------------------------------------------------------

  1. 它是【开机自启 + 常驻运行】的服务，权限高
  2. 它在【反复崩溃】—— 三次卡死前都有它的崩溃记录
  3. 它有【图形驱动】（libGLESv2.dll / libMEmuOpengl.dll）
     模拟器类软件挂显卡驱动，卡死系统很常见
  4. 它的依赖 MSVCR100.dll（VC++ 2010 运行库）出问题
     -> 可能运行库损坏或版本冲突

  结论：这是目前唯一有"崩溃 + 高权限 + 图形驱动"三特征的东西，
        且时间点吻合。优先处理它。


------------------------------------------------------------
五、建议的处理办法（按推荐顺序）
------------------------------------------------------------

【方案 1】禁用服务（最简单，可逆）  ⭐ 推荐先试这个
   效果：不再开机自启，不再常驻
   代价：如果哪天想用"应用分身/手机 App"功能，要重新启用
   做法：
       以管理员身份运行 PowerShell，执行：
       Stop-Service LEmuSVC -Force
       Set-Service LEmuSVC -StartupType Disabled
   或者图形界面：
       按 Win+R -> 输入 services.msc -> 找到 LEmuSVC
       -> 右键属性 -> 启动类型改"禁用" -> 点"停止" -> 确定

【方案 2】从联想电脑管家卸载/更新 FusionEngine
   路径：联想电脑管家 / Lenovo Vantage -> 相关功能里找
         "应用分身""手机协同""FusionEngine" -> 关闭或卸载
   效果：根治，连文件一起清掉
   注意：可能连带影响联想的"手机投屏/多屏协同"等功能

【方案 3】修复 VC++ 运行库
   因为崩溃模块是 MSVCR100.dll（VC++ 2010）
   下载安装：Microsoft Visual C++ 2010 Redistributable (x64)
   效果：可能解决崩溃，但如果模拟器本身有 bug 就无效

【方案 4】先观察（不改任何东西）
   记下每次卡死的【时间】和【当时在干什么】
   下次卡死后，回来对比 Application Log 里 LemuService 的崩溃时间
   如果又吻合 -> 基本确认
   如果明显不吻合 -> 我继续查别的方向

八、★ 已执行的处理（2026-10-13 22:15）
============================================================

操作：禁用 LEmuSVC 服务
方式：提权 PowerShell 执行 Stop-Service + Set-Service

结果（三方独立确认）：
  Get-CimInstance  ->  StartMode=Disabled  State=Stopped  PID=0
  sc.exe qc        ->  START_TYPE = 4 (DISABLED)
  进程检查         ->  原 PID 5932 已退出，LemuService 进程已全部退出

修改前：StartMode=Auto  State=Running  PID=5932
修改后：StartMode=Disabled  State=Stopped  PID=0

【为什么禁用不会有影响】
  1. 该服务没有任何服务依赖它（ServicesDependent 为空）
  2. 全盘搜索：.apk 文件 0 个 —— 从没装过安卓应用
  3. 无应用数据目录（%APPDATA%\Lenovo\LEmu 等均不存在）
  4. config.ini 的 adUpdate=2026-06-17（出厂日），此后未被使用过
  => 结论：这是出厂预装、从未使用过的组件

【遗留项】
  LEmuDrv.sys 内核驱动仍是 StartMode=System / State=Running
  说明：这个驱动开机仍会加载，服务禁用不影响它
  处理：先观察。如果卡死问题消失，就不用管驱动；
        如果还卡死，下一步再考虑禁用驱动（需重启，风险略高）

九、接下来 3 天怎么观察
============================================================

  [ ] 10/15 有没有卡死？时间？当时在干什么？______

三种结果对应三种判断：

  A. 3 天都没卡死
     -> 基本确认 LEmu 就是元凶。保持禁用即可，不用再动。

  B. 又卡死了，但 Application Log 里不再有 LemuService 崩溃
     -> LEmu 洗清嫌疑，是别的原因。需要继续查（下一步查驱动、
        显卡驱动、Windows 更新 KB5129195 安装失败那条线）。

  C. 又卡死了，而且还有 LemuService 崩溃记录
     -> 服务虽然禁用了但被别的东西拉起来了，需要进一步处理。

【怎么查有没有再崩】
  以管理员身份运行 PowerShell，执行：
      Get-WinEvent -FilterHashtable @{LogName='Application'; ProviderName='Application Error'} -MaxEvents 20 |
        Where-Object { $_.Message -match 'LemuService' } |
        Select-Object TimeCreated
  或者直接告诉我，我帮你查。
